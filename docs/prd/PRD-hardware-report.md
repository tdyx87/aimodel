# PRD：本机硬件报告（aimodel v0.1）

> 本 PRD 由 `product-manager` 角色产出。
> **阅读约定**：每条结论带证据标签，便于区分事实与待确认假设。
> `[实测]` = 本仓库构建产物实际测量所得　`[已实现]` = 代码中已存在
> `[仅声明]` = 文档承诺但代码中**不存在**　`[待确认]` = 需产品负责人裁决

---

## 1. 背景与问题

用户想知道「我的电脑能不能跑 AI、能跑多大的模型」，但现状是：

1. 用户不知道自己的**显卡型号与显存**，也不知道**内存与磁盘剩余空间**是否够用；
2. 这些信息散落在系统的不同入口里，要查多个地方、还要看懂专业术语；
3. 用户担心这类工具会把硬件信息上传出去。

**已有依据**：`agents.md` 第 1 节已定义产品定位（面向最终用户、安装即用、失败有友好提示、隐私数据不出本地）；`README.md` 已以用户视角描述该功能。

**本阶段定位**：v0.1 交付「本机硬件报告」这一个用户可感知的能力，作为后续自动选型的地基。

---

## 2. 目标（用户可感知）

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 用户双击启动后，无需配置即可看到本机硬件清单 | 端到端实测 |
| G2 | 用户能读懂每一项数据的含义（非技术术语） | 界面卡片文案 |
| G3 | 用户明确知道数据没有离开本机 | 界面常驻隐私标识 |
| G4 | 检测失败时用户得到可操作的提示，而非空白或报错 | 错误态设计 |
| G5 | 零安装依赖：不需用户安装运行时、配环境变量 | 交付形态 |

## 3. 范围

### 3.1 本期交付（Must）

面向用户展示五类本机硬件信息：**处理器、显卡、内存、硬盘、打印机**。
`[已实现]` 依据：`src/cpp/system_info*.cpp`、`web/` 三个静态文件、`tools/system_info_ui.cpp`。

### 3.2 明确不做（本期范围外）

| 项 | 状态 |
|---|---|
| 自动选择推理设备（显卡/CPU） | `[仅声明]` README 第 30 行承诺，代码中无任何推理引擎 |
| 按显存匹配模型大小 | `[仅声明]` 同上，无模型选择逻辑 |
| 实际运行 AI 模型 / 本地推理 | `[仅声明]` 仓库无推理引擎、无模型文件、无模型加载代码 |

> ⚠️ **必须裁决**：README 已向用户承诺「自动选模型、自动用显卡/CPU 跑 AI」，但该能力**尚未实现**。这构成对用户的超前承诺。产品负责人需在以下两项中裁决：
> - **(a)** 认可 v0.1 只交付硬件报告，将自动选型划入 v0.2，并**同步修改 README 措辞**避免误导；
> - **(b)** 维持承诺，将自动选型拉回本期范围（需大幅扩展排期）。

## 4. 用户画像

**主画像：关心 AI 但不懂技术的普通用户**
- 想知道「我的电脑能不能跑 AI」，但不知道怎么看硬件参数；
- 不接受命令行与 JSON，期望打开就能看到结果；
- 对上传硬件信息敏感，倾向不信任"联网检查"类工具。

**次画像：帮他人排查问题的用户**
- 需要一份可保存、可转发给他人的报告。

## 5. 用户故事与验收标准

> 格式：作为<角色>，我希望<能力>，以便<价值>。每条附 Given/When/Then。

### US-1 打开即见硬件清单
作为关心 AI 的普通用户，我希望打开产品就能看到本机硬件清单，以便判断我的电脑能做什么。

- **Given** 产品已构建并启动
- **When** 浏览器打开产品地址
- **Then** 页面自动加载并展示处理器、显卡、内存、磁盘、打印机五类信息，无需我点击任何按钮

### US-2 读懂每项数据的含义
作为不懂技术的用户，我希望每项数据都用人话说明它意味着什么，以便我不用去查术语。

- **Given** 硬件报告已加载
- **When** 我查看任一张卡片
- **Then** 卡片显示具体数值与通俗说明，不出现 JSON 字段名、`_bytes` 等技术标识

### US-3 知道数据不出本机
作为注重隐私的用户，我希望界面上明确看到"数据只在本机"，以便放心使用。

- **Given** 页面任意状态
- **When** 我查看界面
- **Then** 隐私标识常驻可见（不因刷新或滚动消失）

`[实测]` 端到端验证：运行期唯一网络连接为 `127.0.0.1` 监听套接字，**零出站连接**。

### US-4 失败时得到友好提示
作为普通用户，我希望检测失败时看到我能看懂的处理办法，以便知道下一步做什么。

- **Given** 服务异常或某项检测失败
- **When** 页面加载或刷新
- **Then** 显示「无法获取硬件信息 / 请确认 aimodel 正在运行」类文案与重试入口，不显示堆栈、错误码或技术细节
- **And** 页面不出现白屏

### US-5 零门槛使用
作为普通用户，我希望双击就能用，以便不必安装运行时或配置环境。

- **Given** 用户拿到产品
- **When** 双击启动
- **Then** 自动打开本机浏览器展示界面，无需用户执行构建命令或安装额外软件

`[待确认]` 当前形态要求用户**先执行 `scripts/build.ps1` 构建**才能运行，尚未提供免构建安装包。免构建交付属 `release-engineer` 职责，v0.1 是否包含需裁决。

### US-6 报告可保存转发（次画像）
作为帮他人排查的用户，我希望得到一份可保存、可发送的文本报告，以便发给别人帮我看。

- **Given** 需要一份可转发的报告
- **When** 我使用 `system_info_cli` 输出
- **Then** 得到完整文本报告，可用 `--compact` 得到单行便于粘贴

`[待确认]` `system_info_cli` 按角色定义属**开发者/脚本工具**，其输出为 JSON。是否需为普通用户提供图形化的"复制/导出报告"入口需裁决。

## 6. 非功能需求（含实测基线）

| # | 项 | 要求 | 实测基线 `[实测]` |
|---|-----|------|-----------------|
| NFR-1 | 冷启动（首次运行） | ≤ 5 s 内出结果 | CLI 首次 4366 ms |
| NFR-2 | 热启动（重复运行） | ≤ 1 s 内出结果 | CLI 稳定 ~140 ms |
| NFR-3 | 服务就绪 | 启动到首个有效响应 ≤ 3 s | 681 ms |
| NFR-4 | 单次请求 | ≤ 200 ms | 稳态 9–14 ms（均值 12 ms） |
| NFR-5 | 内存占用 | 运行时 ≤ 50 MB | 工作集 6.8 MB |
| NFR-6 | 交付体积 | 可执行体 ≤ 10 MB | `system_info_ui.exe` 72 KB + 静态资源 23 KB |
| NFR-7 | 隐私 | **零出站连接**、零遥测 | `[实测]` 运行期仅 127.0.0.1 监听，无出站 |

> NFR-1 与 NFR-2 的 30 倍差距值得关注：首跑开销来自进程冷启动（含工具链首次初始化）。若产品化后用户常态是"每次双击只跑一次"，则**冷启动才是真实体验**，需按 ≤5 s 达标并持续观察，不能以热启动数字对外承诺。
