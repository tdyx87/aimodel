# PRD：文件传输（File Transfer）

> 产出者：product-manager
> 审计：product/docs/audit/2026-10-12-product-manager-prd-file-transfer.md

---

## 1. 背景与问题

当前 `aimodel` 主要面向“系统信息报告”场景，用户可以在浏览器里查看本机硬件报告。  
但在真实使用中，用户经常需要把**文件**拿到本机或发到本机，导致两个问题：

1. 无法从浏览器内直接下载本机上某个文件；
2. 无法把浏览器里的文件上传/保存到本机指定目录。

因此需要增加一组“文件传输”能力，作为系统信息报告功能的补充。

---

## 2. 目标（用户可感知）

| 编号 | 目标 | 衡量方式 |
|------|------|----------|
| G1 | 用户可在浏览器内触发文件下载 | 点击后获取可访问的文件 |
| G2 | 用户可将文件上传到本机目录 | 上传后文件出现在指定目录 |
| G3 | 上传和下载路径均在授权目录内 | 无路径穿越现象 |
| G4 | 操作有明确的成功/失败提示 | 界面和日志均可见 |
| G5 | 权限边界清楚：仅服务端授权目录可访问 | 无越权读取 |

---

## 3. 范围

### 3.1 必须做

1. 提供 `POST /api/file/upload`：将上传数据保存到服务端授权目录。
2. 提供 `GET /api/file/download`：按服务端授权的文件名或路径下载文件。
3. 服务端必须校验上传/下载路径，禁止 `../` 等路径穿越。
4. 界面需给出成功/失败提示。

### 3.2 应做

1. 限制上传文件大小（默认 `10 MB`）。
2. 禁止目录遍历：路径归一化后必须在白名单目录内。
3. 下载响应支持 `Content-Type` 自动估算。

### 3.3 不做

1. 不做通用文件管理器；
2. 不做实时同步；
3. 不做外部云存储；
4. 不做复杂授权/用户体系。

---

## 4. 用户故事（Given/When/Then）

```text
US-1 上传一个小文件
  User：普通用户。
  Given：用户打开文件传输页面，并看到“上传区域”。
  When：用户选择一个小文件并提交。
  Then：界面提示上传成功，并给出保存位置。

US-2 禁止路径穿越
  User：用户可能误输入/恶意输入路径。
  Given：上传请求包含 `../` 或绝对路径。
  When：服务端收到路径请求。
  Then：服务端拒绝请求，并返回错误，不写入目标目录。

US-3 下载一个已上传文件
  User：用户上传一个文件后。
  When：用户点击“下载”。
  Then：浏览器获得文件，文件内容与上传内容一致。
```

---

## 5. 验收标准

| ID | 验收点 |
|----|--------|
| US-1 | 上传小文件后界面提示成功 |
| US-2 | 路径穿越请求被拒绝 |
| US-3 | 下载文件内容一致 |
| US-4 | 未授权目录被拒绝 |
| US-5 | 文件大小超限被拒绝 |
| US-6 | 失败时显示可理解提示 |

---

## 6. 非功能需求

| 项 | 要求 |
|----|------|
| 安全 | 必须防路径穿越 |
| 性能 | 上传路径必须不阻塞核心服务 |
| 兼容 | 不破坏现有 `system_info_ui` 主页 |
| 规模 | 默认支持 `10 MB` 文件；可扩展 |
| 隐私 | 服务端只处理用户主动传输的文件，不自动下载用户数据 |

---

## 7. 风险 / 阻塞事项

- 当前仓库缺少实际的文件传输实现；需要先做接口、服务端校验、目录白名单。
- 需要 `security-reviewer` 复核路径穿越逻辑。
