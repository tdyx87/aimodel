# PRD：存档查看器

| 字段 | 内容 |
|------|------|
| 产品名 | 存档查看器（Save Inspector） |
| 版本 | 0.1（首个可交付版本） |
| 状态 | 待 G1 门禁评审 |
| 角色 | `product-manager` |

---

## 1. 问题与用户

### 1.1 用户遇到的真实问题

游戏存档是二进制文件。玩家和客服在三类场景下会卡住：

1. **存档疑似损坏**：游戏读不进去、进度回退，玩家不知道发生了什么，也无法自救。
2. **想查看自己的进度**：玩家想知道"我到底解锁了哪些成就/攒了多少道具"，游戏本体往往不提供这种视图。
3. **客服排查**：玩家报障并把存档发过来，客服需要一个工具看清"哪个槽位、坏在哪"。

现状是这些场景都落到「用文本编辑器打开二进制文件」——不可行。

### 1.2 目标用户

| 用户 | 占比预期 | 核心诉求 |
|------|---------|---------|
| 玩家 | 主要 | 看懂自己的存档；存档坏了知道该怎么办 |
| 客服 / QA | 次要 | 快速定位损坏位置与原因 |

> 两者使用同一个工具，无模式切换——客服能力是玩家能力的超集。

## 2. 用户故事与验收标准

> 每条需求均为**用户场景**表述，验收标准为 Given/When/Then。
> 「可感知」指用户能直接观察到的现象，不接受 API 能力作为需求表达。

### US-1 打开一个存档文件

**Given** 用户已启动本工具
**When** 用户选择了一个存档文件（`.sav`）
**Then** 2 秒内出现槽位列表；**或者**出现明确的诊断结论（不能是空白、不能是白屏）

**边界**：文件不是存档（如选错了图片）时，也必须在 2 秒内给出可理解的原因，而不是报错或空白。

### US-2 浏览存档槽位

**Given** 存档已成功打开且含至少一个槽位
**When** 用户浏览列表
**Then** 每个槽位同时显示：槽位号、最后游玩时间、进度摘要（关卡/金币）、健康状态（正常/异常）

**边界**：空存档（0 个槽位）时显示空状态并说明如何创建槽位，不显示空白列表。

### US-3 查看单个槽位详情

**Given** 列表中某槽位
**When** 用户点开该槽位
**Then** 显示完整数据：当前关卡、金币、道具清单（名称+数量）、已解锁成就、累计游玩时长、最近游玩时间

**边界**：槽位数据部分损坏时，**仍显示能读出的部分**，并标出损坏的字段，而不是整槽拒绝显示。

### US-4 导出存档内容

**Given** 用户已查看某槽位详情
**When** 用户点「导出」
**Then** 生成一个 JSON 文件，其内容与界面所见一致
**且** 导出内容中**不含**用户本机的文件路径

### US-5 损坏诊断

**Given** 存档存在损坏
**When** 用户打开该存档
**Then** 界面回答三个问题：**哪里坏了**（如"第 2 号槽位"）、**为什么坏**（如"校验和不匹配，可能被其他工具改过"）、**我能做什么**（如"请用游戏本体打开一次并重新存档"）

**硬约束**：诊断文案不得出现错误码、堆栈、文件偏移量等开发者术语。

### US-6 兼容旧版本存档

**Given** 用户有一个旧版本格式的存档
**When** 用户打开
**Then** 工具自动升级并在界面标注「已从旧版本升级」，功能正常可用

**硬约束**：**不得修改用户原始存档文件**（全程只读打开）。升级结果只在内存与导出内容中体现。

### US-7 导出为可读文本

**Given** 用户在槽位详情页
**When** 用户点「导出可读报告」
**Then** 得到一份纯文本摘要，可直接贴进客服工单

## 3. 非功能需求

> 全部为用户可感知项，验收标准同样为 Given/When/Then。

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| NFR-1 | 启动快 | Given 用户双击启动，When 界面出现，Then 2 秒内可交互 |
| NFR-2 | 大存档不卡死 | Given 一个 100 MB 的存档，When 用户打开，Then 界面保持可响应，不崩溃、不长时间无响应 |
| NFR-3 | 数据不出本机 | 全程无任何出站网络请求；无遥测、无崩溃上报 |
| NFR-4 | 跨平台 | Windows / macOS / Linux 三平台行为一致 |
| NFR-5 | 不误伤用户数据 | 任何操作都不写入、不修改、不删除用户的原始存档文件 |

---

## 4. 明确不做（本期范围外）

| 项 | 理由 |
|----|------|
| 写回存档 | 与 NFR-5 冲突；写坏存档的风险远大于本期收益 |
| 解密加密存档 | 需要游戏方密钥，本期无获取途径 |
| 多游戏格式支持 | 先做透一种格式，再谈扩展 |
| 存档云同步 | 与 NFR-3 冲突，且本期无服务端 |
