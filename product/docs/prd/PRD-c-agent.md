# PRD：低内存终端 Agent 助手（C 实现）

| 字段 | 内容 |
|------|------|
| 角色 | `product-manager` |
| 时间 | 2026-10-15 |
| 分支 | `feat/c-agent` |
| 定位 | 类 opencode 的终端 AI 编码代理，用 C 实现，**极低内存占用**是其第一性约束 |

---

## 1. 问题陈述

现有终端 AI 代理工具普遍以 TypeScript / Python / Go 实现，常驻内存多在
**80～150 MB** 量级。这在容器、小内存机器、CI runner、多开几个终端标签的
日常场景里是真实负担——而这类代理会**常驻**（打开终端就开着），
内存不是峰值问题而是**基线问题**。

用 C 实现不是为了炫技，而是因为这个场景里，内存占用是**架构决定**的：
是否无上限地缓冲响应流、是否把整个文件读进内存、是否让会话历史无限增长。
这些选择在任何语言里都能做对，但只有 C 会让代价显式到无法忽视。

**本产品的第一性约束：内存。** 功能完整度排在其后。

## 2. 目标用户与场景

| 用户 | 场景 |
|------|------|
| 在小内存 VPS / 容器里工作的开发者 | 同时开着 5~10 个代理会话，内存不能叠加失控 |
| 大量开终端标签的重度用户 | 每个标签常驻一份代理，基线内存决定一天下来多少 RAM |
| 受限环境的 CI runner | 内存上限严格，代理需要与其他任务共存 |
| 关注可预测性的人 | 要能一句话问出「它现在占了多少内存」，而不是看个大概 |

## 3. 用户故事

### US-1 启动即用

**Given** 我在项目目录下运行 `cagent`
**When** 它读取配置并连接配置的模型服务
**Then** 我看到一个输入框，界面可立即输入，无需加载动画或索引预热

**验收**：从进程启动到出现可输入提示符 < 500 ms（含配置读取与网络握手）

### US-2 对话与流式回复

**Given** 我输入一句话
**When** 模型开始回复
**Then** 回复内容**逐字出现在界面上**，而不是等全部生成完再一次性出现

**验收**：从发出请求到首个字符上屏 < 2 s（正常网络）；逐字渲染期间界面不卡顿

### US-3 读取文件

**Given** 代理需要看某个文件
**When** 它调用读文件工具
**Then** 我看到它读了哪个文件、读了什么内容

**验收**：支持至少 4 种规格（大文件自动分段、超大文件截断并显式告知、二进制文件拒绝并说明原因、空文件正常返回）

### US-4 修改文件

**Given** 代理要改文件
**When** 它请求写入或编辑
**Then** 我**先看到它想做什么**，再决定批准还是拒绝

**验收**：
- 任何写入类操作前必须有确认，默认拒绝
- 确认提示显示：目标文件、改动摘要（行数增减）、可用的 diff
- 拒绝后代理必须收到明确的「已拒绝」反馈并能继续对话，而不是中断

### US-5 执行命令

**Given** 代理要执行 shell 命令
**When** 它请求执行
**Then** 我看到完整命令与预期风险，同样可以拒绝

**验收**：同样走确认流程；命令输出超过阈值时分页/截断而非无限累积

### US-6 会话可恢复

**Given** 我昨天开过一个会话
**When** 我今天重新启动
**Then** 我能列出历史会话并继续其中之一

**验收**：会话以文件形式落盘，可列出、恢复、删除；损坏的会话文件不应导致程序无法启动

### US-7 随时知道内存占用

**Given** 我想知道它现在吃了多少内存
**When** 我执行内置的内存查询
**Then** 我拿到一个**具体数字**（RSS），而不是模糊描述

**验收**：内置命令输出 RSS 峰值与当前值；这是产品的对外承诺，必须可被第三方独立复核

### US-8 多服务兼容

**Given** 我用不同的模型服务
**When** 我在配置里切换
**Then** 工具调用行为保持一致，用户不需要改用法

**验收**：至少支持 OpenAI 兼容格式与一种非兼容格式（差异在适配层，用户不可见）

## 4. 非功能需求

### NFR-1 内存占用（本产品的核心指标）

| 指标 | 目标 | 说明 |
|------|------|------|
| 空闲基线 RSS | **≤ 8 MB** | 启动后空闲、无会话 |
| 活跃会话 RSS | **≤ 15 MB** | 单会话，含历史消息与工具结果 |
| 超长会话 RSS | **≤ 25 MB** | 500 轮对话后 |
| 单次大文件读取增量 | **≤ 4 MB** | 读 50 MB 文件时的增量 |
| RSS 硬上限 | **≤ 32 MB** | 任何情况下不得突破；触及即中止并报错 |

**测量口径**：进程 RSS，取自操作系统（Windows 用 `GetProcessMemoryInfo`，
POSIX 用 `/proc/self/statm` 或 `getrusage`），**不采用库自己的估算**——
库估的和系统看到的可能差很远，承诺必须以系统数字为准。

**参照基线**：同类工具（TypeScript / Go 实现）常驻 80～150 MB。
若本产品实测落在 10 MB 以内，节省 90%+ 才是本产品存在的理由。

### NFR-2 响应延迟

首个字符上屏 < 2 s。流式渲染期间主循环不得因 UI 重绘而卡顿。

### NFR-3 安全性

- 工具调用**默认全部需要确认**，不存在「静默执行」
- 路径访问限制在工作区内，逃逸（`..`、符号链接指向外部）必须拒绝
- 不得把 API key 写入日志或会话文件
- 不得执行来自模型输出的、未经用户确认的命令

### NFR-4 可移植

Windows / Linux / macOS 三平台可编译、可运行。终端原始模式、进程控制、
路径处理三处跨平台差异必须收拢在平台适配层，不得泄漏到业务逻辑。

## 5. 明确的范围边界

### 5.1 不做

| 项 | 理由 |
|----|------|
| 图形界面 | 终端是本产品的形态，GUI 会引入无法控制的内存基线 |
| 插件系统 / MCP | 会让内存不可控，且与「极低内存」冲突 |
| 向量索引 / 语义检索 | 需要常驻索引，与内存预算矛盾；先用 ripgrep 式的字面搜索 |
| 多代理并行 | 并行会成倍放大内存基线，与 NFR-1 冲突 |
| 自动压缩历史 | 先用定长截断 + 明确提示，把取舍摆到明面上而不是藏起来 |

> 上述「不做」里，**向量索引与并行**是最可惜但必须砍的：
> 它们是内存大户，砍掉它们正是本产品与通用代理的差异所在。

### 5.2 与同类工具的差异

| 维度 | 通用代理 | 本产品 |
|------|---------|--------|
| 内存 | 80~150 MB | **≤ 15 MB** |
| 工具确认 | 可配置为默认允许 | **默认全部拒绝** |
| 历史管理 | 自动压缩（不透明） | 定长截断 + 明示 |
| 依赖 | Node/Python 运行时 | 单二进制（libcurl 静态或动态） |

## 6. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|------|------|------|
| 1 | **会话历史无界增长**——这是本产品最可能违反 NFR-1 的地方 | 活跃会话 RSS 失控 | 契约层定死：历史窗口按字节封顶，超出按轮次淘汰**最旧的完整轮次**，并在界面上明示已丢弃多少 |
| 2 | 工具结果（尤其是读大文件）直接进对话 | 瞬时暴涨 | 读文件按字节上限截断 + 行号标注 + 显式告知「已截断」 |
| 3 | SSE 流被整体缓冲后再解析 | 峰值内存 = 响应大小，违背 NFR-1 | 传输层**强制**增量回调，不提供「读全量」的接口——让犯错在编译期不可能 |
| 4 | libcurl 自身的缓冲不受控 | 传输层成为黑箱 | 只用写回调（CURLOPT_WRITEFUNCTION）流式喂入，不设 WRITEDATA 大缓冲；并在 NFR-1 实测中把 curl 的占用一并计入 |
| 5 | 第三方 TLS/JSON 依赖引入额外内存 | 预算被侵蚀 | 依赖清单固定为 libcurl；JSON 解析自己写定长扫描器，不引第三方 JSON 库 |

> 风险 3 与 4 是本产品成败的分水岭。若为了实现方便写了「读全量响应」的接口，
> 后面所有优化都只是化妆。**契约层就要把它堵死。**

## 7. 验收标准

| # | 标准 | 判定方式 |
|---|------|----------|
| A1 | NFR-1 全部指标达标 | 第三方脚本独立测 RSS（不引用产品自己的报告） |
| A2 | US-1~US-8 全部有 E2E 用例 | 每个故事至少一条端到端用例，含拒绝路径 |
| A3 | 破坏性操作全部走确认 | 存在「默认拒绝」的测试用例 |
| A4 | 三平台编译通过 | CI 矩阵全绿 |
| A5 | 路径逃逸被拒 | 构造 `../` 与符号链接逃逸用例，断言拒绝 |

> A1 用**第三方脚本**而非产品内置命令判定，是为了避免「自己给自己打分」。
> 内置的内存查询（US-7）服务于用户，两者不能是同一个东西。
