## 2. 关键决策

1. **形态定为「纯文本流」**，不做全屏 TUI。理由：NFR-1（低内存）与非 TTY 可消费优先；
   全屏需要布局与重绘，收益不抵成本。被否决的备选：curses 式全屏——内存与可脚本性都变差。
2. **批准交互固定为单字符 `[y/N]`，且无默认值**。理由：回车即同意会把一次误触变成一次写盘。
3. **待批准内容在询问之前**，用分隔线收尾。理由：P2/P5 要求用户先看清再答。
4. 启动显示工作区与会话目录（本次补）。理由：用户批准写入时必须知道目标目录。
5. **非 TTY 不加任何装饰**（无横幅、无等待提示、无 ANSI）。理由：管道输出要可被脚本直接消费。
6. 明确列出**不做的**（颜色、行编辑、状态栏、全屏），避免「没写 = 忘了」。
