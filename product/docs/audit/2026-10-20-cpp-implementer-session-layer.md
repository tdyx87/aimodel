## 2. 关键决策（含被否决的备选）

| 决策 | 理由 | 被否决的备选 |
|------|------|-------------|
| 历史用**单块定长缓冲 + 偏移表**（`recs[i] = {role, off, len}`） | 预算是硬约束，容量在初始化时定死；淘汰靠 `memmove` 前移，**不做任何再分配**，内存上界可证 | 动态字符串数组（`char **`）—— 每次追加都可能触发分配，且碎片化不可控 |
| 淘汰按**整轮**（从一条 user 到下一条 user 之前） | 拆开淘汰会让模型看到孤立的助手回复，比少一轮更糟：它会以为用户说过没说过的话 | 按条淘汰 —— 简单，但会产生不一致的对话 |
| 流式片段用 `append_delta` **续写末条助手消息**，而不是每条片段新增一条 | 逐 token 回调会瞬间耗尽 `CA_SESSION_MAX_MSGS`；续写还能把「正在写的这条」从淘汰中保护出来 | 每条 delta 一条记录 —— 条数上限会被流式打爆 |
| 淘汰/截断的**数量与字节**记在 notice 字段，由 UI 读取即清 | T3 要求「淘汰发生且 UI 有明示」；把事实留在数据层，界面只是呈现，可测 | 直接在 `session` 里打印 —— 数据层不得依赖 UI |
| 落盘/目录扫描全部关进 `session_store.c` | 契约 §8：平台差异不得泄漏进业务逻辑。`session.c` / `core.c` / `main.c` 里没有任何 `#ifdef _WIN32` 的业务分支 | 在 `session.c` 里就地 `#ifdef` —— 会把平台细节混进核心逻辑 |
| 写文件**先 `.tmp` 再 `rename`** | 中途失败留下临时文件不会顶掉一份好会话；直接覆盖时写坏就等于丢数据 | 直接 `fopen(path,"wb")` |
| 损坏文件**照常列出并标注**，而不是静默跳过 | 静默跳过时用户只看到「会话不见了」，而原因（文件损坏）其实可查。契约 §6 原措辞是「跳过并提示」，实现后回写契约并说明理由 | 静默跳过 —— 会丢可发现性 |
| 读取**按预算封顶**，而不是「文件多大读多大」 | 会话文件是外部输入，可被人为放大；不封顶就等于把「内存可预测」交给别人决定 | 完整读入再判断 |
| 每轮成功即落盘，退出再补一次 | 崩溃/断电至多丢一轮，而不是整段对话 | 只在退出时保存 —— 会话越长丢得越多 |
| 保存时若 id 不可信则**换新 id**，而不是报错 | 用户的对话不该因为文件名可疑就丢掉（修复见 `adad080`） | 直接失败 |
| 复用 `json` 层的两遍写入器，不在 `llm.c` 里再维护一份转义表 | C6 零分配 + 单一实现；此前 `llm.c` 自带转义表属重复 | 各自维护 —— 两处转义规则迟早分叉 |

## 4. 实现过程中的修正（完整记下，不藏）

| # | 问题 | 性质 |
|---|------|------|
| 1 | `S_IFDIR` 在严格 C99 的 Linux 上未声明 | 跨平台。本机只编 Windows，由 CI 的 Linux 腿抓到 |
| 2 | `file_times()` 在非 Windows 分支未被使用 | 告警（零告警是硬门禁），同上由 CI 抓到 |
| 3 | 测试手拼路径触发 GCC `-Wformat-truncation` | 同类问题出现两次（`adad080`、`53d78c7`），最终把路径拼接收敛到 `ca_session_path_for` |
| 4 | `append_delta` 容量边界越界写 1 字节、破坏 `used <= cap` | **内存安全**，G2 审查发现（`adad080`） |
| 5 | 保存时用载入的 id 拼路径 → 可路径穿越 | **安全**，G2 审查发现（`adad080`） |
| 6 | POSIX 会话文件按默认权限 0644 创建 | 隐私，G3 安全审查发现（`03e5902`） |
| 7 | `ca_session_to_json` 在「只计量」那遍也判容量，导致 `buf=NULL` 用法永远失败 | 逻辑缺陷，单测先红暴露 |

> 第 1、2 条的共同教训：**本机只编 Windows 时，「能编译、能过测试」不能推出「三平台都对」**。
> 第 4、5、6 条的共同教训：**外部输入的边界（容量边界、文件名、权限）必须单独设计，而不是靠正常路径顺带覆盖**。
