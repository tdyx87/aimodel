## 1. 输入

- 用户指令：提供凭据以验证 release 条件 **C2**（真实第三方 HTTPS 跑通一轮，含一次工具批准）。
- 端点 `https://open.bigmodel.cn/api/paas/v4`、模型 `GLM-4.7-FLASH`；凭据只存在于进程环境变量。

## 2. 关键决策

1. **C2 不接受「本地假服务」的等价物**：仓库里所有冒烟都跑在本地假服务上，
   它们证明协议与批准通道正确，却**证明不了真实服务会给想要的东西**。
   真实故障正是这么暴露的——请求体里没有 `tools`，模型只会聊天，
   而伪造 `tool_calls` 帧的脚本化测试全绿。
2. **凭据不入库**：只经环境变量传入，不写文件、不进会话文件、不进审计正文；
   同时提醒用户：密钥已在对话中明文出现，**建议轮换**。
3. **版本口径不上调为 1.0**：C1/C2/C3 是本项目自定的「稳定门槛」，现已全部达成，
   因此 `0.1.0` 的「未达稳定门槛」标注可以撤销；但版本号本身**不变**——
   遗留项（标准 tool 握手、正则搜索、US-8、ASAN、性能实测）都是真存在的，
   把它们说成已完成就是撒谎。

## 3. 产出

| 轮次 | 缺陷 | 处理 |
|------|------|------|
| 第一次真实调用 | 界面只显示「请求失败 / 无法解析的内容」 | 定位到两个根因：`header_cb` 把**响应头长度**当状态码；4xx 错误体被丢弃。已修，并新增 `HTTP %ld: <服务端 message>` 呈现 |
| 第二次真实调用 | 模型把工具调用当**文本 JSON** 输出，还幻觉「已成功写入」（文件不存在） | 定位到根因：请求体**没有 `tools` 字段**。已修：tools 层提供 Schema、请求体带上 `tools`、core 分发表补 `search` |
| 第三次真实调用 | 工具结果回灌后模型**原样再要一次同一个工具** | 加「工具已执行 / 被拒绝（未执行）」措辞；标准握手列为遗留项（reviewer R9） |
| 第四次真实调用 | 同一错误**连出两行** | `main` 与 `core` 重复打印，已删其一 |

**验证结果**：`scripts/real_api_smoke.py` → `RESULT: PASS (chat=ok, memory=ok, tool=ok)`；
`ctest` 8/8；`core_test` 200 检查 0 失败；`mem_load` 峰值 7.6 MB。

**新增可重复手段**：`product/scripts/real_api_smoke.py`（凭据只读环境变量，429 自动重试并与真失败分开计数）。
