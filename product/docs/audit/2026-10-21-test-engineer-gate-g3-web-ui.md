## 3. 为什么工具腿用**本地脚本化服务**而不是真实服务

真实服务当前对本账户返回 429（code 1113「额度不足」/1305「模型过载」）。
拿它当门禁 = 拿 flaky 当门禁：今天绿、明天红，而且红了也不知道是代码坏了还是服务端限流。
本地脚本化 SSE 服务（与 `tool_smoke.py` 同一手法）能**确定性地**回一个 `tool_calls`，
于是「浏览器批准 → 代理执行 → 文件落盘」这条链可以被反复验证。
真实服务的验证另有 `real_api_smoke.py` 承担。

## 4. 新增的冒烟覆盖了什么

| 检查 | 守住的缺陷 |
|------|-----------|
| 页面可取且含 EventSource | 页面没内嵌/没被截断 |
| **无令牌 → 401** | 鉴权形同虚设（本机任意网页可驱动代理） |
| **带令牌 → 200** | 令牌校验写反了（曾因头部截断导致带令牌也 401） |
| POST /api/send → 200 | 消息进不了代理 |
| SSE 收到事件 | 事件没广播出去（曾因 `sse_send` 截断丢事件，页面只看得见首条 info） |
| 批准事件 → 允许 → **文件落盘** | 批准链路断了（浏览器点按钮没反应） |
| 落盘内容正确 | 执行的不是模型要求的内容 |

## 5. 未覆盖（如实登记）

1. **真实浏览器的观感**（布局、颜色、滚动、Enter/Shift+Enter 行为）无法在 CI 里验证：
   没有浏览器自动化依赖（不引第三方）。已用「HTML/JS 人工检查 + 协议层冒烟」兜底。
2. **多客户端并发**（两个浏览器同时连）未测；只测了单客户端。
3. **跨平台**：两个冒烟脚本只用标准库，但 Windows/macOS/Linux 的差异（socket 语义、
   端口分配）由 CI 三平台实跑来覆盖；本地只验了 Windows。
4. **令牌过期/重放**无测试（当前实现也没有过期语义，属已知弱化项）。
