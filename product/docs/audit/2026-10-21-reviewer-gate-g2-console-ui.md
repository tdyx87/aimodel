## 2. 审查清单

| # | 检查项 | 结论 | 依据 |
|---|--------|------|------|
| R1 | ANSI 转义是否可能泄漏到**非 TTY** | 通过 | 所有装饰只经 `ca_ui_*` 出口，且每个函数都先判 `is_tty`；`ui_plain_mode_never_emits_decoration` 断言非 TTY 输出中不含 `\x1b[`。CI 跑的就是这条路径 |
| R2 | 可视化代码是否越过 ui 层进入业务逻辑 | 通过 | core/main 只调用 `ca_ui_*`，不写转义序列；符合「平台差异收拢于 `ca_term_*`」 |
| R3 | `--probe` 是否可能泄露 key | 通过 | 只打印「已设置/未设置」；`Authorization` 头只放进请求，不进输出。响应片段最多 255 字节且来自服务端回包 |
| R4 | `--probe` 在缺配置/无 libcurl 时是否**给出明确结论** | 通过 | 缺 `CAGENT_API_BASE`/`CAGENT_MODEL` → 走既有 usage 路径，退出码 2；无 libcurl → 明确打印「本构建没有可联网的后端」，退出码 1 |
| R5 | 失败文案是否**可行动** | 通过 | 连接/TLS/超时/4xx/无法解析各有独立文案，4xx 还分「有/无可读原因」两支；附目标主机名（不含路径与凭据） |
| R6 | Windows 原始模式是否还让 Ctrl-C 失效 | 通过（已修） | 原实现清了 `ENABLE_PROCESSED_INPUT` → Ctrl-C 不再产生中断，用户只能强杀。已改为只清 `ENABLE_LINE_INPUT|ENABLE_ECHO_INPUT` |
| R7 | 中断/强杀后终端是否被留在坏状态 | **发现问题，已修** | 原先只在正常退出路径还原控制台模式；Ctrl-C 打断时进程直接结束，终端留在**无回显**状态（用户症状：敲什么都不显示）。已加 `SIGINT` 处理函数：先 `ca_term_raw_exit()` 再 `_exit(130)` |
| R8 | 盒面板是否折叠/截断**待批准内容** | 通过 | 面板按行原样输出，不折叠；`ui_panel_keeps_every_body_line` 断言三行都在。P2/P5 要求批准前看到完整内容 |
| R9 | 盒面板对超长单行是否安全 | 通过 | 面板缓冲 1024 字节，拷贝前检查 `head + len + 2 < sizeof(row)`，放不下时退化为直接输出原行（不截断、不溢出） |
| R10 | 是否引入**告警**（CI 硬门禁） | 通过 | 编译零告警。过程中出现过两处：MSVC 对含中文格式串的 C4474、`strncat` 的 C4996；都已改为「格式串纯 ASCII + 中文作参数」与 `memcpy` |
| R11 | 改动是否影响**非 TTY 消费者** | 通过 | 非 TTY 输出逐行与改动前等价（多了错误文案分类，但那是修复本身）；三个冒烟脚本（curl/session/tool）与 `mem_load` 均通过 |

## 3. 遗留（记录，不阻塞）

- `--probe` 目前只做一次 `ping` 请求，不覆盖工具调用链路（那要真实写文件），保持「只读诊断」的定位是对的。
- 可视化层没有做**表格化**输出（如 `/list` 的会话列表）；当前仍是逐行文本。
- 颜色只用 8 色基础 SGR，未适配 256 色/主题；不同终端下观感会有差异，属可接受范围。

✅ 通过，放行 G3。
