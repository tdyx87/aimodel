## 1. 输入

- 用户原话：「增加可视化ui 我自己测试为什么什么都不显示呢 显示错误 请求失败」。
- 复现环境：Windows 控制台（代码页 936）、真实 GLM 服务、`build-curl\Release\cagent.exe`。
- 契约 §7（终端界面）、§8（平台差异收拢于 `ca_term_*`）、U4（非 TTY 不加装饰）。

## 2. 关键决策

| 决策 | 理由 | 被否决的备选 |
|------|------|--------------|
| 把「请求失败」拆成**可行动的失败类别**（连不上 / TLS / 超时 / 4xx / 无法解析），并附目标主机 | 真实复现：域名拼错时界面只给「请求失败」，用户完全不知道该改地址、换代理还是等额度。**说「无法连接到服务端（目标：x）」才可行动** | 保留「请求失败」并在文档里解释——用户不看文档 |
| Windows 启动时 `SetConsoleOutputCP(CP_UTF8)` + 打开 ANSI | 简体中文控制台默认代码页 936，UTF-8 中文按 GBK 解释就是**乱码**；用户看到的现象是「界面什么都不显示」。这是与程序逻辑无关的纯平台问题 | 让用户自己 `chcp 65001`——把责任推给用户不算修好 |
| Windows 原始模式**不再关 `ENABLE_PROCESSED_INPUT`** | 关掉它，Ctrl-C 不再产生中断，进程退不出去，用户只能强杀；而强杀不会还原控制台模式，终端被留在**无回显**状态，之后敲什么都不显示——用户视角就是「程序把我的终端搞坏了」 | 保留关闭 + 文档提醒——用户仍会踩 |
| 加 `SIGINT` 处理函数：先 `ca_term_raw_exit()` 再退出 | 中断路径也必须还原终端，否则同样留下坏终端 | 只依赖正常退出路径还原——恰恰是 Ctrl-C 这条路径最容易漏 |
| 新增 `cagent --probe` 诊断命令 | 用户报「什么都不显示」时，最需要的不是解释而是**事实**：地址、模型、key 有没有、后端是什么、服务端回了什么。一次性打印，且**不打印 key** | 让用户自己用 curl 试——门槛太高，且和程序实际请求不完全等价 |
| 可视化层放在 `ca_ui`（`heading/kv/panel/ok/warn/error/note`），非 TTY 全部退化为纯文本 | 装饰与平台能力都留在 ui 层，符合「差异不得泄漏到业务逻辑」；CI 跑的就是非 TTY 路径，**装饰若泄漏进管道就是回归** | 在 core/main 里直接写 ANSI——会让非 TTY 输出变脏，且无法单测 |
| 盒面板**不折叠正文** | 契约 P2/P5：批准前必须看到完整内容（路径、命令原文） | 折叠长内容以「清爽」——等于让用户盲批 |
| 失败文案用 ASCII 冒号（`HTTP 429: …`） | MSVC 对含中文的格式串误报 C4474，零告警是 CI 硬门禁；中文只作参数传 | 用全角冒号——每次构建都红 |

## 3. 产出

| 文件 | 变更 |
|------|------|
| `src/core.c` | 新增 `core_note_transport_error()`：按 `ca_http_status_text()` 给出连接/TLS/超时类别并附目标主机；4xx 分「有可读原因 / 无可读原因」两支；错误行改用 `ca_ui_error()`（TTY 红色） |
| `src/ui.c` / `include/cagent/ui.h` | 新增可视化 API：`ca_ui_heading/kv/panel/ok/warn/error/note`；非 TTY 全部退化为纯文本；盒面板按行输出，不折叠 |
| `src/ui_term.c` / `include/cagent/ui.h` | 新增 `ca_term_setup_console()`：Windows 设 UTF-8 代码页 + 打开 ANSI；原始模式不再清 `ENABLE_PROCESSED_INPUT` |
| `src/main.c` | 启动调用 `ca_term_setup_console()`；注册 `SIGINT` 处理（先还原终端再退出）；启动画面改为「标题 + 键值行 + 后端/模型」；新增 `--probe` 诊断命令与帮助条目 |
| `tests/ui_test.c` | 新增 3 例：TTY 下有装饰且错误为红色（`\x1b[31m`）、**非 TTY 下不含任何 `\x1b[`**、面板保留每一行正文 |
| `design/ui-terminal.md` | §2 启动画面改版、新增 §11 视觉层、§12 `--probe`、§13 失败文案表 + Windows 平台要求 |
| `README.md` | 新增 §3.0「界面什么都不显示 / 报请求失败」排查表（对着 `--probe` 输出逐条对照） |

**验证**

- 本地：`ctest` **8/8**；`ui_test` **63 检查 0 失败**（含 3 条新用例）；编译零告警。
- **复现对照**（修复前 → 修复后）：
  - 域名不存在：`错误：请求失败` → `错误：无法连接到服务端（目标：no-such-host-xyz.invalid）`
  - 地址指向本地未监听端口：`错误：请求失败` → `错误：无法连接到服务端（目标：127.0.0.1:9）`
  - 缺 key：`错误：请求失败` → `错误：HTTP 401: Header中未收到Authorization参数，无法进行身份验证。`
- `--probe`：地址/模型/key 有无/后端/HTTP 状态/响应片段/结论，一次打印齐备；实测 429 与 401 两种情形都给出了服务端原文。
- 真实服务回归：`real_api_smoke.py` 工具链路仍通过（工具调用界面、批准提示、文件真的落盘）。

## 4. 结论

用户反馈的两件事都已处理：**失败不再是一句无信息的「请求失败」**，界面在 Windows 控制台上
也不会再是乱码/空白；并按要求补上了可视化 UI（标题、键值、盒面板、颜色分级），
且**非 TTY 路径保持纯文本**（CI 契约未破）。完成并移交 G2。
