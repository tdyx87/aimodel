## 3. 新增用例与「能证伪什么」

| 用例 | 断言要点 | 能证伪的缺陷 |
|------|----------|--------------|
| `list_dir_prints_chinese_name_as_utf8` | 结果里能找到 UTF-8 的「测试文件」 | 列举用 ANSI API → 中文名乱码（用户实测看到的现象） |
| `write_and_read_chinese_filename_roundtrip` | 写中文名文件 → 列举得到同名 → 读回内容 | fopen 走系统代码页 → 中文路径写不出/读不回 |

**修复前确实红**：两条用例在改动落地前分别以「名字是乱码」和「写入返回非 OK」失败。

**fixture 的坑（已修）**：中文名文件必须用**宽字符** API 创建；
用 fopen 写 UTF-8 字节会建出另一个名字，fixture 本身就是错的，
断言会指向错误的地方。测试改用产品自己的 `ca_tool_fopen`（顺带避免了
`windows.h` 把 `small` 定义成宏、污染无关变量的问题）。
