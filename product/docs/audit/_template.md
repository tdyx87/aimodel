# 审计文档模板

复制本文件为 `<YYYY-MM-DD>-<role>-<task>.md` 后填写。
规范见 `.role-system/agents.md` §6.6；所有字段均为**必填**，
「无」也要显式写「无」，不能留空。

| 字段 | 内容 |
|------|------|
| 角色 / 时间 / 任务 | 谁、何时、做了什么任务（一句话） |
| 结论 | 角色级裁决：`reviewer` 写 ✅/❌；`security-reviewer` 写风险分级（无 Critical/High 方可放行）；其余角色写「完成并移交」 |

## 1. 输入

消费的上游产物，**带路径引用**（PRD/契约/代码/测试/上游审计）。

## 2. 关键决策

做了什么选择 + **理由**，含被否决的备选。理由不成立时审计会忠实记下这个错误，
所以宁可写「依据不足，这是猜测」。

## 3. 产出

生成的产物及路径（文件、报告、结论）。**结论必须能回到产物**——
不能只写「已审查」。

## 4. 结论

同上表的「结论」字段，此处可展开为判断依据。

## 5. 移交

交给下游哪个角色、下游该依据什么开工。

## 6. 复核（由独立复核者填写，非自证）

| 复核人 | 时间 | 结论 | 说明 |
|--------|------|------|------|
| （orchestrator / 下游角色） | | 通过 / 打回 | 核对「产出」「结论」是否与产物一致、「关键决策」理由是否成立 |

> 未填写本节的审计**不构成放行依据**：审计记录的是操作者声明的理由，
> 不等于客观正确（`agents.md` §6.6）。
