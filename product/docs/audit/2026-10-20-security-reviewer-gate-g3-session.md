## 1. 输入与范围

## 2. 方法

把会话层当作「**唯一由用户可写文件回灌进内存**的输入面」来审——凡是它读的东西
（文件内容、文件大小、文件数量、文件名、id 字段、权限）都不默认可信；
凡是它写的东西（目标路径、权限、内容）都当成可被他人观察的资产。
逐项对照威胁模型：路径穿越、资源耗尽、信息泄露、内存安全、注入。

## 3. 发现

| # | 严重度 | 类别 | 问题 | 处置 |
|---|--------|------|------|------|
| S1 | **High** | 路径穿越 | `ca_session_save` 用 `s->id` 拼文件名，而 id 可来自载入文件的 `"id"` 字段：`../../pwned` 可把用户数据写到会话目录之外 | **已修复**（`adad080`）：保存全程走 `ca_session_path_for` 校验；可疑 id 直接弃用并生成新 id（不让保存失败）。回归用例 `session_save_does_not_follow_traversal_id` |
| S2 | **High** | 内存安全 | `ca_session_append_delta` 在容量边界把 NUL 越界写到 `buf[cap]`，并让 `used = cap+1` 破坏 `used <= cap` | **已修复**（`adad080`）。归入安全审查是因为越界写是内存安全问题，不只是逻辑缺陷 |
| S3 | Low → **已修复** | 信息泄露 | POSIX 上会话文件按默认权限创建（`0666 & ~umask`，通常 **0644**），同机其他用户可读私人对话 | **已修复**（`03e5902`）：临时文件写完、改名之前 `chmod 0600`；用例 `session_file_is_not_world_readable`（Linux/macOS 腿执行） |
| S4 | Low | 依赖风险 | libcurl 未逐条核对 CVE 数据库；仅依赖「发行版/vcpkg/自建」提供版本 | **残留**，见 §5 |
| S5 | Info | 隐私（设计选择） | 会话文件明文存储用户对话 | **接受**，见 §5 |

## 4. 逐项核对（通过项，附依据）

| 核对项 | 结论 | 依据 |
|--------|------|------|
| 密钥不落盘/不进日志（NFR-3） | ✅ | 密钥只存在于 `ca_core_config`；`session` 结构只有消息文本，JSON 里无钥匙字段。用例 `session_json_never_contains_key_field`、`session_saved_file_has_no_key` 断言落盘内容既无 `api_key` 也无 `Authorization` |
| 路径穿越（V5）在**删除**路径上 | ✅ | `ca_session_delete` 拒绝含 `/`、`\`、`..` 的 id；用例 `session_delete_refuses_path_traversal` |
| 路径穿越在**恢复**路径上 | ✅ | `main` 的 `/resume` 经 `ca_session_path_for` 校验后拼接 |
| 无字节上限的增长（V2/V6） | ✅ | 历史 4 MB 封顶；**读文件也按预算封顶**（`read_file_capped`），不随文件大小增长；损坏/超长文件按轮次淘汰或显式截断 |
| 资源耗尽 | ✅ | 列表一次最多 `min(条数, cap)`；内容校验复用一个临时会话，额外内存是常数份 |
| 远程输入面 | ✅ | 会话层不发网络请求；唯一的出网是 core→transport，且密钥不随会话持久化 |
| 遥测 | ✅ | 本产品无遥测；无隐式上报 |
| 注入 | ✅ | 会话内容不进入任何 shell；工具执行仍走「默认拒绝」权限模型（本层未削弱） |
| JSON 解析器被恶意输入攻击（深度/递归） | ✅ | 游标式扫描，`from_json` 只进一层对象/数组，无递归解析；截断/畸形内容由 9 组损坏用例覆盖 |
| Windows 侧权限 | ✅ | `%APPDATA%` 已是用户私有；无需额外 mode 处理（S3 只在 POSIX 适用） |

## 5. 残留风险（不阻塞放行，但必须记在案）

| 编号 | 风险 | 分级 | 说明与建议 |
|------|------|------|-----------|
| S4 | libcurl 依赖的 CVE 状态未逐条核对 | **Low** | 传输层只是 libcurl 的使用方；建议在 release 检查单里加一条「记录构建所用 libcurl 版本」，而非在本门禁阻塞 |
| S5 | 会话文件明文存储用户对话 | **Low（信息性）** | 这是**产品设计选择**：用户需要能在本地恢复自己的会话，端到端加密会与「本地可读、可编辑、可删除」直接冲突。缓解措施已到位——文件不改名不外发、POSIX 0600、密钥不落盘。用户应知晓该文件的存在（需 `doc-engineer` 在用户文档中写清） |
