## 3. 为什么要重开

原 G3 的结论是真实的：在那个环境下 ctest 36/36、E2E 20/20 全绿。**问题不在结论真假，
而在「环境」没有被当作受控变量**：

| 项 | 事实 |
|----|------|
| 缺陷 | 产物对**静态资源**的第一个请求即 SIGSEGV（退出码 `0xC0000005`），整个界面不可用 |
| 触发条件 | 运行时 PATH 上第一个 `libstdc++-6.dll` 来自另一版本的 GCC（本机 Git for Windows 的 mingw64） |
| 为何 API 全绿 | 崩溃点位于 libstdc++ 的流/文件缓冲路径，只有静态资源分支走到那里——**「接口测得通」恰好掩盖了「页面打不开」** |
| 为何 E2E 没拦下 | E2E 跑在 PowerShell 环境，那里 PATH 无 Git 的 mingw64，DLL 解析恰好正确 |

结论：**「在某个环境里全绿」不等于「产物可用」**。G3 的核心条件（单测 + E2E 全绿）
在字面上被满足过，但门禁要防的「用户拿到手就坏」并没有被防住，故重开。
