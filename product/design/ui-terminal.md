# 终端界面稿（cagent 0.1.0）

> 角色：`ui-designer`。本文是**界面行为契约**：所有文案、顺序、出现条件是实现与测试的基准。
> 与实际代码不一致时，以本文为准改代码，或先改本文并写明理由——不允许两者长期不一致。
> 形态：**纯文本流界面**（无全屏、无布局引擎）。一个字符都不能影响管道消费。

## 1. 原则

| # | 原则 | 理由 |
|---|------|------|
| U1 | 破坏性动作**先展示、后询问**，默认否 | 用户必须看清「要动哪个文件、写什么」才谈得上同意（契约 P1/P2/P5） |
| U2 | 代理做了什么**当场可见**，不只可事后查 | 否则用户是在黑盒里看着代理改自己的文件 |
| U3 | 丢失/截断必须**当面说明**（给数字） | 「历史过长已截断」等于没说清丢了什么 |
| U4 | 非 TTY 下不加任何装饰 | 输出要能被脚本直接消费（契约 §7） |
| U5 | 不做全屏重绘 | 重绘是卡顿主因；逐 token 追加即可（契约 §7） |

## 2. 启动（仅 TTY）

```
cagent —— 低内存终端代理（C99）
输入 /help 查看命令，/exit 退出。
工作区：E:\workspace\aimodel
会话：C:\Users\me\AppData\Roaming\cagent\sessions
```

- 工作区 = 启动时的当前目录，**工具只能读写它内部**。启动就显示，是因为用户批准写入时
  必须知道「写到哪」。
- 会话目录不可用时第三行改为：`会话：（目录不可用，仅保存在内存中，退出即丢失）`。
- 离线自检模式（`CAGENT_TRANSPORT=mem`）在启动后**立即**补一行：
  `离线自检模式：不发起任何网络请求，回复是预设内容。`
  ——不说明的话，用户会把预设回复当成模型真实回答。
- 非 TTY：以上全部不打印（避免污染管道）。

## 3. 输入提示

```
> 
```

- 空行不发请求（省一次计费调用）。
- 超过 4095 字节整行丢弃并提示：`输入过长，已丢弃该行（上限 4095 字节）。`
- 以 `/` 开头视为命令，不进模型。

## 4. 等待与流式

请求已发出、首个 token 未到时（仅 TTY）：

```
（等待响应…）
```

- 任何真实输出到来时**先擦掉这一行**再写字；本轮没有文本（例如只调工具）则在收尾时擦掉。
- token 逐段追加，**不**全屏重绘、**不**回卷已输出内容。
- 非 TTY：不出现等待行，且**不得出现任何 ANSI 转义**（有用例守着）。

## 5. 工具批准（核心交互）

展示顺序固定：**待批准内容 → 分隔线 → 询问 → 回答回显 → 收尾分隔线**。

```
将写入文件：notes/todo.md
内容 37 字节：

- 买牛奶

--- write_file 请求。允许执行？[y/N] y
--- 
```

规则：

| 项 | 规定 |
|----|------|
| 默认值 | **没有默认值**：只认 `y` / `Y`。回车、其它键、EOF 全部按拒绝处理 |
| 输入 | 读**一个字符**，不回显除该字符外的任何东西 |
| 拒绝回显 | `--- ` 收尾行必须出现，让用户知道询问已结束 |
| `run_shell` | 展示**完整命令原文**，不折叠、不省略（P5） |
| `write_file` | 展示目标路径 + 内容；内容超过 2048 字节只展示开头，并**显式标注** `[以上仅前 N 字节，共 M 字节]` |
| `edit_file` | 展示影响面：匹配处数、行数增减、文件未被修改 |
| 策略否决 | 用户答 `y` 之后，产品策略仍可否决（如 `run_shell` 未开 `CAGENT_ALLOW_SHELL=1`），并说明`（按策略拒绝执行命令：…）` |

## 6. 工具调用与结果

```
[调用工具 write_file]
<result status="ok" path="notes/todo.md" bytes="37">已写入。</result>
```

- 工具被拒时：`<result status="denied" …>` 后跟一行 `已拒绝该工具调用，未做任何改动。`
- 工具失败时结果里必须带**可行动的原因**（路径越界/无法写入/超时…），不能只说「失败」。
- 工具轮次到上限：`已达到工具轮次上限，停止执行更多工具。`

## 7. 命令

| 输入 | 输出形态 |
|------|---------|
| `/help` | 命令表 + 两行批准说明 |
| `/mem` | `当前 RSS：x.xx MB` / `峰值 RSS：x.xx MB` / `传输后端：<name>` / `会话历史：used / budget 字节，N 条消息` |
| `/new` | `已开始新会话。`（只清内存，不删磁盘上的旧会话） |
| `/list` | `会话（新到旧，共 N 个）：` 后逐行 `  <id> N 条消息`；损坏文件照常列出并标注 `[损坏，已跳过]`；空时为 `（还没有历史会话）` |
| `/resume <id>` | `已恢复会话 <id>：N 条消息。`；id 非法：`无效的会话 id（id 见 /list）。`；坏文件：`无法恢复：该会话文件损坏或不存在（未做任何改动）。` |
| `/delete <id>` | `已删除会话 <id>。`；失败：`删除失败：<id>（id 是否正确？）`；id 含 `/`、`\`、`..` 一律拒绝 |
| `/exit` | 保存会话并打印 `本次会话已保存：<id>（用 /resume <id> 继续，/list 查看全部）` |
| 未知命令 | `未知命令：<原文>（/help 查看可用命令）` |

## 8. 错误与提示

| 场景 | 文案 |
|------|------|
| 一轮失败 | 空行 + `错误：<可读原因>`（网络/协议/上限），随后回到提示符，**不退出** |
| 历史淘汰 | `（会话历史已达上限，丢弃最早的 N 条消息，共 M 字节）` |
| 单条过长被截断 | `（有 N 条消息过长被截断，共丢弃 M 字节）` |
| 会话目录不可用 | 启动时说明一次；`/list`、`/resume`、`/delete` 如实报「不可用」 |
| CLI 未知选项 | stderr：`未知选项：<原文>（见 --help）`，退出码 2 |
| Ctrl-C / EOF | 正常退出（先落盘），不打印错误 |

## 9. 非 TTY 降级对照

| 元素 | TTY | 非 TTY（管道/重定向） |
|------|-----|----------------------|
| 启动横幅与工作区/会话行 | 有 | 无 |
| 等待提示 | 有 | 无 |
| ANSI（清行/颜色/光标） | 有（仅清行） | **绝不** |
| 提示符 `> ` | 有 | 有（保持逐轮可读） |
| 批准询问 | 单键读取 | 同样单键读取（脚本可喂 `y`/`n`） |
| 流式追加 | 有 | 有（按 token 原样） |

## 10. 当前**不做**的（如实记录）

| 不做 | 原因 / 后续 |
|------|------------|
| 彩色/加粗/语法高亮 | 颜色在重定向与日志里是噪音；留待「可选主题」议题 |
| 行编辑（方向键、历史） | 需要完整 termios/Console 行编辑器；当前由终端自身承担 |
| 状态栏、进度百分比 | 无可靠进度来源；假进度比没有更糟 |
| 全屏 TUI / 分栏 | 与「低内存、可管道消费」目标冲突 |
