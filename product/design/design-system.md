---

## 1. 设计取向

本工具的使用场景与 aimodel 不同：**用户在排查问题，处于焦虑状态**。因此设计取向是「**诊断优先**」：

- 界面主角是**存档的数据与状态**，不是操作按钮；
- 任何异常都必须**先说结论、再给依据**（PRD US-5），不能只给一个红色感叹号；
- 颜色用于**编码状态**，不用于装饰。

---

## 2. 色彩

| 用途 | 色值 | 说明 |
|------|------|------|
| 背景 | `#0E1116` | 与 aimodel 一致，减少切换产品的割裂感 |
| 表面 | `#161B22` | 卡片 |
| 主文 | `#E6EDF3` | |
| 次文 | `#8B949E` | 单位、辅助说明 |
| 强调 | `#2F81F7` | 可交互、链接 |
| 正常 | `#3FB950` | 槽位健康、已解锁 |
| 警告 | `#D29922` | 已升级、字段缺失但可读 |
| 异常 | `#F85149` | 损坏、不可读 |

> 语义色的使用规则：颜色**必须**与文字同时出现，不得仅靠颜色传达状态（可访问性）。

---

## 3. 排版与间距

- 字号：标题 20px / 卡片标题 16px / 正文 14px / 辅助 12px
- 间距基数 4px，常用 8 / 12 / 16 / 24
- 行宽 ≤ 72 字符（诊断文案可读性优先）
- 等宽字体用于：文件名、导出内容、道具 ID

---

## 4. 组件规范

每个组件必须定义 **default / hover / disabled / error / empty** 五态。

### 4.1 槽位卡片（SlotCard）

槽位列表的每一项，是本界面的核心组件。

| 状态 | 表现 |
|------|------|
| default | 表面色卡片；左侧 4px 竖条表示健康状态 |
| hover | 表面色提亮；出现「查看」按钮 |
| active/selected | 强调色描边 |
| healthy | 竖条为正常色 |
| degraded | 竖条为警告色 + 「部分字段不可读」角标 |
| corrupt | 竖条为异常色 + 「已损坏」角标；**仍可点击查看能读出的部分** |
| empty | 槽位号 + 「空槽位」；无进度数据 |

**必备字段**（PRD US-2）：槽位号、最后游玩时间、进度摘要、健康状态。

> `corrupt` 态**必须可点击**——这是 PRD US-3 的硬要求（部分损坏仍显示能读出的部分）。不可点击等于把「整槽拒绝」写进设计。

### 4.2 诊断条目（DiagnosticItem）

| 元素 | 内容 |
|------|------|
| 严重级图标 | ⓘ 警告 / ⚠ 错误 / ✓ 正常（同时配文字，不只靠图标） |
| 标题 | 「哪里坏了」——如「第 2 号槽位校验和不匹配」 |
| 说明 | 「为什么坏」 |
| 建议 | 「你能做什么」——**必须有**，可执行 |

三段式不可省略中间或末段（PRD US-5）。

### 4.3 数值展示（StatValue）

大数值 + 单位 + 语义色（如金币为异常高时标警告）。单位统一：时长用「X 小时 Y 分」，不用秒；字节用 KB/MB/GB。

### 4.4 空状态（EmptyState）

| 场景 | 文案方向 |
|------|---------|
| 未选择文件 | 「选择或拖放一个存档文件开始」+ 按钮 |
| 存档 0 槽位 | 「这个存档还没有任何槽位」+「用游戏本体创建并保存一次」 |
| 搜索无结果 | 「没有匹配的槽位」 |

## 6. 可访问性硬要求

- 所有交互元素可键盘到达，焦点态可见
- 诊断条目的严重级**不依赖颜色**传达
- 正文对比度 ≥ 4.5:1
- 屏幕阅读器可播报诊断条目（`role="status"` / `aria-live`）
- 拖放区必须同时提供**点击选择**与**键盘可达**的等价入口（拖放不能是唯一途径）
