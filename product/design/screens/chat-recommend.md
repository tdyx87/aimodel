# 界面稿：聊天/推荐模块（chat-recommend）

> 产出者：`ui-designer`，交付 `frontend-implementer`。
> 依据：`docs/prd/PRD-chat-system.md`、`docs/design/chat-system-contract.md`。
> 定位：在**现有硬件报告页**上增量加入一个「对话/推荐」模块；不改动现有卡片顺序、布局、刷新与隐私标识（PRD US-6）。

---

## 1. 位置与线框

模块作为独立卡片，置于**硬件报告卡片组之后、文件传输卡片之前**（用户看完配置后自然发问）。名称：**问问我的电脑**。

```text
┌─ 问问我的电脑 ────────────────────────────────────────────┐
│  ┌─────────────────────────────────────────┐  ┌────────┐  │
│  │ 我这台电脑能跑多大的模型？               │  │  发送  │  │
│  └─────────────────────────────────────────┘  └────────┘  │
│  试试这样问：                                              │
│  [ 能跑 7B 模型吗？ ] [ 推荐一个合适的模型 ] [ 显存够吗？ ] │
│  ───────────────────────────────────────────────────────  │
│  （提问后显示结果区）                                      │
│  ┌ 推荐 ─────────────────────────────────────────────┐    │
│  │ ✅ 可以运行                                        │    │
│  │ 当前配置可能支持 7B 级别模型的粗略推荐……            │    │
│  │ 本机配置摘要                                       │    │
│  │   处理器：Intel Core i5-10500                      │    │
│  │   显卡：AMD Radeon R7 430 · 2.0 GB 显存            │    │
│  │   内存：16.0 GB（可用 3.0 GB）                     │    │
│  │   磁盘：最大可用分区剩余 1.2 GB                    │    │
│  │ 下一步                                             │    │
│  │   1. 先确认显存 — 当前显卡显存为 2.0 GB — …        │    │
│  └───────────────────────────────────────────────────┘    │
│  ⓘ 本回答为本地规则建议，未调用外部模型，数据不出本机。    │
└───────────────────────────────────────────────────────────┘
```

- 输入框为单行 `input`（回车或点「发送」提交）；`textarea` 非必要，保持轻量。
- 快捷问题为**按钮**，点击即填入并提交，降低首用门槛。
- 结果区仅在提问后出现，不与首屏硬件报告争夺注意力。

---

## 2. 状态设计（四态齐备，对应 design-system §6）

| 态 | 触发 | 视觉 | 文案 |
|----|------|------|------|
| 空态 | 首次进入，未提问 | 输入框 + 快捷问题按钮；结果区隐藏 | 占位符「我这台电脑能跑多大的模型？」 |
| 加载 | 已提交，等待返回 | 发送按钮转圈并禁用；结果区显示骨架块 | 顶栏 `aria-live` 播报「正在根据你的配置给出建议…」 |
| 结果 | 返回 `ok:true` | 分类徽标 + 理由 + 配置摘要 + 下一步 + 隐私说明 | 见 §3 |
| 错误 | 网络失败 / 超时 / `ok:false` | 结果区错误态 + 重试按钮 | 「暂时无法给出建议，请确认 aimodel 正在运行，然后重试。」 |

分类徽标（结果态）：

| 分类 | 徽标文案 | 语义色 |
|------|---------|--------|
| `recommend` | 可以运行 | `--success`（绿） |
| `check` | 需要检查 | `--warn`（黄） |
| `not_recommended` | 不建议 | `--danger`（红） |

> 不用颜色单独传达状态：徽标始终「色 + 文字」并存（design-system §7）。

---

## 3. 结果区结构（字段级）

结果区自上而下：

1. **分类徽标**：`recommend` / `check` / `not_recommended` 三选一，配中文文案。
2. **理由**：`recommendations[0].reason` 全文（含不确定性声明）。
3. **本机配置摘要**：由 `config_snapshot` 提取，逐行「标签：值」——
   - 处理器：`cpus[0].brand`
   - 显卡：`gpus[*].name` + 显存（`video_memory_bytes`，为 0 显示「共享内存」）
   - 内存：`memory.total_bytes`（可用 `memory.available_bytes`）
   - 磁盘：取 `disks[*].free_bytes` 最大者，显示「最大可用分区剩余 X」
4. **下一步**：`recommendations[0].next_steps[]`，每条为「序号 + title — detail — action」。
5. **隐私说明**（常驻于结果区底部）：固定文案
   「本回答为本地规则建议，未调用外部模型，数据不出本机。」

---

## 4. 交互规则

1. 提交前 `trim` 输入；空输入不提交，输入框下方提示「请先输入一个问题」。
2. 提交中禁用发送按钮，防止重复请求。
3. 请求超时（10 秒）走错误态，可重试（保留上次输入）。
4. 快捷问题点击 = 填入 + 立即提交。
5. 结果替换而非追加（本期不做多轮对话记忆，见 PRD §3.2）。
6. 键盘：输入框回车提交；快捷问题与发送按钮可 Tab 聚焦，焦点环 `2px --accent`。

---

## 5. 错误文案（用户语言，不暴露技术细节）

| 场景 | 文案 |
|------|------|
| 空输入 | 请先输入一个问题 |
| 网络失败 / 服务未运行 | 暂时无法给出建议，请确认 aimodel 正在运行，然后重试。 |
| 请求超时 | 建议请求超时，请重试。 |
| 服务返回 `ok:false` | 直接展示 `error.message`（服务端已给用户语言文案） |

---

## 6. 约束

- 复用 `design/design-system.md` 的 CSS 变量与既有类（`.card`/`.btn`/`.row`/`.list`），不新增硬编码颜色。
- 不引入任何 CDN / 外部字体 / 运行时外部请求（离线可用）。
- 不改动现有硬件报告卡片与文件传输卡片的 DOM 结构与顺序。

---

## 7. 交付验收（frontend-implementer 完成标准）

1. 与 §1 线框一致：卡片位置、输入 + 快捷问题、结果区四态齐备。
2. 结果区含分类徽标、理由、配置摘要、下一步、隐私说明五部分。
3. 断网/服务断开显示错误态 + 重试，不白屏。
4. 键盘可达 + 语义化标签 + `aria-live` 播报。
