## 2. 状态矩阵

| 状态 | 表现 |
|------|------|
| 正常 | 全部区块渲染，底部两个导出按钮可用 |
| 部分字段不可读 | 能读的正常显示；不可读字段**就地标注**（如「（已损坏）」），**不整块隐藏、不整槽拒绝** |
| 空槽位 | 各区块显示占位（如「道具（0）」），导出按钮仍可用 |
| 整槽损坏 | 显示可读部分 + 顶部诊断条；导出按钮禁用（导不出有意义的内容） |

> 「就地标注」是 US-3 的硬要求：整槽拒绝显示等于把可恢复的信息也丢了。

---

## 3. 导出交互

| 按钮 | 行为 | 失败表现 |
|------|------|---------|
| 导出 JSON | 下载 `.json`，内容与界面所见一致 | 就地提示，**不离开当前页** |
| 导出可读报告 | 下载 `.txt` | 同上 |

**实现约束**（继承 aimodel 教训，见契约 §4）：

- 必须走 `fetch` + blob，**禁止** `window.location.href`——后者在服务端返回错误 JSON 时会把用户踢出整个界面；
- 导出文件名不得含用户本机路径；
- 按钮点击期间禁用，防重复触发。

---

## 4. 数据来源

| 元素 | 契约字段 |
|------|---------|
| 关卡 / 金币 / 时长 | `slot.level` / `coins` / `playtime_sec` |
| 道具 | `slot.items[]` → `{id, count}` |
| 成就 | `slot.achievements[]` |
| 可读性 | `slot.healthy == false` + `diagnostics` |
| 升级标注 | `slot.upgraded == true` 时显示「已从 v1 升级」 |

道具 ID 到名称的映射由核心库在导出/响应中给出，前端不维护映射表（避免前后端两处维护同一份数据）。
