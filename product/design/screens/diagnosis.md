## 2. 三段式（US-5 硬约束）

每条诊断**必须**回答三问，缺一不可：

| 段 | 回答 | 例 |
|----|------|-----|
| 标题 | 哪里坏了 | 第 2 号槽位的数据已被改动 |
| 说明 | 为什么坏 | 数据与写入时记录不一致，通常被其他工具改过 |
| 建议 | 我能做什么 | 用游戏本体打开一次并重新存档；先备份 |

**不得出现**：错误码、文件偏移量、字节数、堆栈、内部函数名。

---

## 3. 各损坏场景的文案（契约 §2.3 逐条对应）

| 场景 | 标题 | 建议方向 |
|------|------|---------|
| 非存档文件 | 这不是存档文件 | 确认是否选错了文件 |
| 版本过新 | 存档来自更新版本的游戏 | 升级游戏后再查看 |
| 文件被截断 | 存档不完整 | 可能在保存时被中断；重新存档 |
| 槽位偏移越界 | 第 N 号槽位的数据位置异常 | 该槽位无法读取，其余槽位可正常使用 |
| 校验和不匹配 | 数据已被改动过 | 用游戏本体重新存档（先备份） |
| 需密钥 | 该存档已加密 | 需要游戏本体才能读取 |
| 旧版本升级（info） | 已从 vN 升级读取 | 无需操作；原始文件未被修改 |

---

## 4. 状态矩阵

| 状态 | 表现 |
|------|------|
| 全部致命（无法解析） | 只显示诊断视图，**不显示**「查看可读内容」按钮 |
| 部分可读 | 显示诊断视图 + 「仍要查看可读内容 →」（跳 `slot-detail.md`） |
| 仅 info（升级提示） | 走正常列表流程，诊断以 info 条嵌入列表顶部（`slot-list.md` §2） |
| 修复后重试 | 「重新选择文件」按钮 |

---

## 5. 可访问性

- 诊断条目 `role="status"`，新增条目时向 `aria-live` 播报；
- 严重级用**图标 + 文字 + 颜色**三重表达，不单靠颜色（设计系统 §6）；
- 「仍要查看可读内容」为主操作，「重新选择文件」为次操作，焦点顺序与视觉顺序一致。
