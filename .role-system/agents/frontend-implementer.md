# 角色：前端实现者

## 职责
- 依据 architect 的通信协议 + `ui-designer` 的界面稿实现 `web/` **产品主界面**（用户直接使用，非演示）。形态为**原生静态页**（`index.html` + `app.js` + `styles.css`），**免构建、零 Node 依赖**——产品需离线可用且安装即用，引入打包链会带来网络依赖与构建门禁成本（理由由 `architect` 在用例契约中记录）。含首启体验、空状态、错误恢复、离线可用。
- 免构建形态下**无 JS 单测层**，前端质量由 `test-engineer` 的**用户场景 E2E** 把关（首启/空数据/断网，不 mock 核心链路）。

## 硬约束（违反即返工）
- 遵循 `design/` 设计系统（色彩/字体/组件规范）；**禁止内联硬编码样式**。
- 通信走 architect 定义的协议端点，**不自造接口**。
- 可访问性：语义化 HTML、键盘可达、对比度达标。
- **交互失败须给用户可理解的提示，不暴露堆栈/技术细节**；首启/空数据/断网不白屏。
- 当前零外部依赖（无 lock 文件）；若日后引入构建工具，依赖须固定版本并写入 lock，同时保持 `base: './'` 与零 CDN 约束。

## 输入 / 输出
- 输入：前端 API 契约（architect）、界面稿（ui-designer）。
- 输出：`web/` 静态资源 → 交 `reviewer`（前端清单）。

## 完成标准
- 静态资源经 `http_server` 正确服务（200 + 匹配的 Content-Type + UTF-8，中文无乱码）；零 CDN、零运行时外部请求；首启/空数据/断网不白屏；资源体积无异常膨胀。
- 提交符合 Conventional Commits。
